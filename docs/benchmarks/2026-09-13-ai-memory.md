# Study: ai-memory as a cross-CLI handoff

- **Date:** 2026-09-13
- **Owner request:** after Continue landed on the terminal `⋯` menu, study
  [akitaonrails/ai-memory](https://github.com/akitaonrails/ai-memory)
  and say whether it changes that plan.
- **Scope:** whether a long-term memory server should replace, wrap, or
  sit beside PiCode's native transcript handoff (ADR-0088). Not an install
  of the server, not a PiCode package door (ADR-0109).
- **Receipts:** README, `docs/ARCHITECTURE.md`, `docs/usage.md`,
  `docs/managed-workstreams.md`, `docs/managed-harness-contributions.md`,
  `docs/support-matrix.md` on `main` / release **v2.2.1** (2026-09-12).
  PiCode has no `ai-memory` symbol today.

## What it is

A Rust MCP/HTTP server. Agents emit sanitized lifecycle hooks; the server
compiles them into a git-backed markdown wiki and serves search (FTS5,
entities, optional vectors). The pitch is the same sentence as ours:
quit Claude Code, open Codex in the same directory, continue.

That sentence hides two layers. They are not interchangeable.

| Layer | What actually moves | How you launch |
|---|---|---|
| Default (hooks + MCP) | A typed `handoffs` row + a session summary page. The next SessionStart (or `memory_handoff_accept`) injects a **brief**. The target CLI's own session is still its own. | You start the CLI yourself in that folder |
| Opt-in `ai-memory run` | A leased workstream. Native transcripts are read **read-only**; a bounded portable delta is injected; returning to a harness resumes **that harness's** linked session. | You must start the CLI through their wrapper |

Their own split (`docs/managed-workstreams.md`): skip the wrapper when a
handoff is all you want — hooks alone already write "where you left off,
what failed, what's open". Use the wrapper only when you want the
harness's native resume to survive a *harness switch* with tool-call
history, not just a summary.

Handoffs are **next-session transfer, not a live bus** (`docs/usage.md`).
One writer may own a workstream at a time. Managed adapters **do not
write** Claude / Codex / OpenCode / Pi / Grok private stores.

## What is true in PiCode today

Continue (ADR-0088/0094) reads a native transcript, projects it through
`internal/transcript`, and **creates** a new native session of the
target (or a deterministic brief under `<dataDir>/handoffs/`). The
Sessions pane and, as of this branch, the terminal `⋯` / pane menu are
the doors. The source terminal stays running. Identity is the ADR-0084
pin. No extra daemon.

## Take / refuse

| Source | Fact | Take / refuse |
|---|---|---|
| Default handoff | Next agent gets a wiki brief in the same cwd; no native `--resume` of the previous conversation | **Refuse as a substitute.** That is our *Brief* mode, not Native session |
| `ai-memory run` | Wrapper + lease + read-only extract + bounded inject | **Refuse as the Continue implementation.** Would wrap Agent CLI launches (ADR-0069), drop create-only writes (the ADR-0088 hole in ADR-0056), and stop the source (their lease vs our "source stays") |
| "Handoffs are not a live bus" | Same refusal as ADR-0088 | **Take** as confirmation. Continue stays a handoff, never a process switch |
| Bounded startup packet | No window can absorb an unbounded transcript | **Already ours:** `window=recent` / last compaction |
| Untrusted injected history | Packets are delimited historical evidence; current instructions and checkout stay authoritative | **Already ours:** the handoff note; thinking never travels |
| Do not write guest stores | Managed adapters are read-only on `~/.claude` / `~/.codex` / SQLite | **Refuse to copy.** Native Continue *is* a new file in the target store, round-trip verified. That is the product |
| Hook install preserves foreign entries | Their installer and Herdr's can share a CLI config | **Take as coexistence:** Activity reporting (ADR-0069) and an optional memory server are two hook files, not a merge |
| Hermes | Community plugin; SessionStart stdout ignored; recover via MCP | **Keep our writer.** Vendor `hermes sessions import` is why Hermes can receive a native Continue at all |
| Grok | Capture works; SessionStart stdout ignored; managed path uses `--rules` | **Keep our Grok writer + `--resume <id>`.** Brief already covers the no-import case |
| Support matrix vs managed set | Twenty-plus harnesses on MCP/hooks; managed resume is a shorter explicit list | **No expansion.** PiCode v1 Agent CLIs stay the ADR-0069 six |

## Decision

**No change to Continue.** The terminal menu still calls
`POST /api/clis/{cli}/sessions/handoff`. `ai-memory` is a complementary
layer (durable wiki + optional wrapper), not a replacement for a native
session the other CLI can `--resume`.

If both run: opening the other CLI in the same folder can inject their
brief *and* PiCode's copied transcript. Two contexts, two products. The
user guide names the split; Continue does not hide itself when hooks
exist.

Adopting `ai-memory run` as the launch path, or shipping ai-memory as a
PiCode package/connector, is a later boundary (protocol + process, and
for a package an ADR-0109 door). Not this branch.

## What we keep (not worth copying)

- Create-only native writers and vendor import (ADR-0088/0094).
- Launch through PiCode terminals, not a third-party wrapper.
- Source terminal stays up (Stop is a different verb).
- Zero extra daemon for Continue.
