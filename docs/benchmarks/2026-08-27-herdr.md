## What it is

A Rust **agent multiplexer**: it owns PTYs (not Electron). Guest CLIs
(Claude, Codex, Pi, …) run in panes. A background server keeps sessions
across detach, lid-close, and SSH. Panes are marked idle / working /
blocked from **screen detection**, not from the guest's own RPC.

PiCode already owns PTYs via **tmux** and structured state via **pi RPC**
(ADR-0002). Herdr is the other bet: one binary that *is* the terminal
runtime and scrapes agent TUIs.

## Refuse

| Temptation | Why not |
|---|---|
| Swap tmux for Herdr's PTY | ADR-0002. PiCode's hatch is the real Pi TUI in tmux. Herdr would own a second runtime and guest-CLI matrix. |
| Screen-scraping pi for "blocked" | We have RPC `waiting`. Scraping is how Herdr supports 20 CLIs; we have one. |
| Guest-CLI multiplexer identity | ADR-0003: user-installed **pi** only. |
| Socket API as our control plane | Same-user socket, no per-agent auth (bench note). We speak HTTP to our binary. |
| Using Herdr as the editor/diff bar | It has none. Track E is Cursor hunks + cwd files (ADR-0015). |

## Relation to Track E

None on the surface. Herdr leaves review to the guest. PiCode's next
track is the opposite: **Keep / Undo** on pi `edit`/`write` and a
CodeMirror pane on the same cwd.

Do not delay E1 for more Herdr reading.

## Relation to worktrees (later)

When we isolate parallel agents, read Herdr `src/api/schema/worktrees`
**and** Orca. Herdr treats worktrees as layout convenience, not
authority containers (bench). We will decide then whether an agent *is*
a worktree or only *has* a cwd.
