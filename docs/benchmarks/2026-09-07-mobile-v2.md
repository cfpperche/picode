# Mobile v2: a complete workspace with focused phone surfaces

Research date: 2026-09-07. Sources are official documentation, product demos
and merged upstream fixes. This is a desk study, not hands-on acceptance of
the referenced products. Adaptations below are PiCode design proposals.

| Source | Evidence | PiCode adaptation |
|---|---|---|
| [Paseo workspaces](https://paseo.sh/docs/workspaces) and [product demo](https://paseo.sh/) | Workspaces collect sessions, terminals, browsers and diffs; the demo includes focused mobile views. | Preserve workspace context while opening one tool across the phone's width. |
| [Replit Mobile](https://docs.replit.com/features/platforms/mobile-app) | Project navigation separates Agent, Tools and Tasks; an artifact bar opens previews. | Contextual tool selection and visible preview access; gestures remain optional. |
| [Cursor mobile](https://prod.cursor.com/docs/cloud-agent/mobile) | Conversation, triage, PR review and cross-device continuation; excludes general editing and terminal tools. | Borrow triage and review ergonomics. Its exclusions do not decide PiCode's scope. |
| [GitHub Mobile](https://docs.github.com/en/get-started/using-github/github-mobile) | Notifications, code search, PR review and editing. | Focused file reading and changes navigation are useful phone capabilities. |
| [Happy](https://happy.engineering/) | Remote local sessions and attention notifications. | Treat blocked questions and reconnection as normal interaction states. |

Specific regression references from Happy: [multiline mobile input](https://github.com/slopus/happy/pull/854),

## Layout and interaction constraints

| Official guidance | Application |
|---|---|
| [Apple tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) | Stable, labelled destinations; keep contextual actions separate and retain navigation state. |
| [Apple sheets](https://developer.apple.com/design/human-interface-guidelines/sheets) | Short, scoped tasks in a sheet; long tasks need the available screen; avoid nested sheets. |
| [Apple buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) | Visible pressed states and generous touch regions. Native 44 pt guidance is not a CSS-pixel requirement. |
| [Android adaptive navigation](https://developer.android.com/develop/ui/compose/layouts/adaptive/build-adaptive-navigation) | Adapt to available window space; compact and wide layouts need different treatment. |
| [WCAG 2.2](https://www.w3.org/TR/WCAG22/) | AA target minimum is 24 CSS px with exceptions; enhanced target is 44 CSS px. Reflow at 320 CSS px, text resize and visible focus matter. |
| [VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport) | Keyboard and zoom affect the visible region; measure height and offset instead of guessing device dimensions. |
| [CSS env()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env) | Apply safe-area insets once at the relevant edge; keyboard handling is separate. |
| [Reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion) | Reduce nonessential motion while preserving state feedback. |

Use 44 CSS px as PiCode's touch-region target. Keep the repository's 36 px
visual control rhythm; surrounding spacing must make targets usable without
overlap. Density comes from removing duplicate controls and nested cards,
not from shrinking text or the actionable area.

## Current baseline

Source: `ded70274`, independent mobile app, disposable fixture at port 18761.
Browser screenshots inspected at 390 x 844, light theme. Evidence stays in
`var/screenshots/mobile-v2/before/` in the implementation worktree.

- Empty Now: clear creation action, but no existing workspace path surfaced.
- Work: nested workspace and item cards; repeated creation rows; paths truncate
  early. The last workspace's creation controls reach the bottom navigation
  in this fixture.
- Stopped agent: header 52 px, state/actions 56 px, stop notice about 64 px;
  empty composer 191 px. The unobscured center spans about y=172..643.
- Agent draft and attachments live in components that unmount on navigation.
- The mobile Agent CLIs copy needs a route audit for nested session screens.

Baseline observations are not a visual PASS for the new design. Physical
iOS/Android keyboard, install, push and resume behavior require device acceptance.
