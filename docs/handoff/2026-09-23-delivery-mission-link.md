# 2026-09-23 — delivery-mission-link: the change says which objective it serves
The reverse half of the Mission ↔ Delivery seam. Missions already cited a delivery as evidence (`Kind: "delivery"`), and its own copy says the seam out loud — "Integration remains a separate action in Delivery" — but nothing on the Delivery side knew missions existed (`grep -c -i mission Delivery.jsx` was 0). Now `store.MissionsByDelivery(workspace)` inverts that link: delivery id → the missions citing it, each mission named once however many criteria point at the same change, paged to a bound above the store's own mission cap with a `truncated` flag rather than a silently short answer. The Delivery read carries it as `missions`, and both surfaces (browser rows/detail and the mobile screen) show the mission's own title, its own state label and a route back to it. A change nobody cites says nothing — absence of a link is not a claim of "no mission".
Read-side only: no schema, no migration, no write, and no authority — nothing here can accept a mission or authorize an integration. The mission stays the owner of the reference; the axes stay separate (objective/criteria/acceptance vs artifact/receipts/merge queue), and the vocabulary rule from the analysis is written into the architecture file: in Missions the assignment receipt is *receipt*, never "delivery", while the evidence kind and the Delivery subsystem keep the word.
Tests: the store inversion (two criteria, one objective; uncited delivery; empty workspace), the read carrying the map and its flag, and the domain helpers (`missionsFor`, `missionLinks`) including a link with no title and an empty list.
Still with the Missions agent: its architecture section, the receipt vocabulary, and the M5 boundary — an executor of its own would collide with ADR-0186's merge queue.

Visual: the desktop Delivery view was captured, measured and audited (`overlayAudit ok`, the link computes to `--accent` `#7c8cf8` against the row's `--text-secondary`, hover underlines it). The **mobile** capture did not render the delivery list in the scratch (the Git ▸ Delivery panel showed only its header, before and after Refresh), so the mobile row is **UNVERIFIED visually** — the code is the same two lines and the domain helpers are shared and tested, but that is not a visual verdict.
