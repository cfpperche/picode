# 2026-09-15 — feat/tmuxcwd: the flake was not test interference

`TestCreateTerminalInWorkspaceUsesItsFolder` failed ~1 run in 3 (twice in this
session's `make ci`/`make close`), always with `cwd` = the *daemon's* working
directory. I first blamed cross-test tmux interference; the mechanism is
narrower and in the product:

**`#{pane_current_path}` read in the same instant as `new-session` answers with
the *server's* directory** — the daemon's cwd — until the pane's command has
spawned. Measured in a loop through the real API: 12 of 30 creation responses
carried it, while the same query a millisecond later was right, and all three
query shapes (display-message on the session, list-panes, display-message on a
pane id) showed the race at the creation instant (6/30, 4/30, 1/30). An empty
server exiting between creations is what opens the window wide.

Fix: the creation response names the folder the session was created in
(`freshTermView`; `ensureShell` now reports whether it created the session, and
the CLI-create and open paths use the same chooser). Every later poll keeps
reading live, which is where a user's own `cd` appears.
Instrumentation used for the diagnosis (a cwd trace in `liveTermCwd`, two
Manager debug methods, a throwaway test) was removed; the diagnosis is recorded
above and in `docs/handoff/open/process.md`.
Tests: `TestCreatedTerminalAnswersWithItsOwnFolder` (8 creations in a row, each
session ended so the next starts a fresh server) — fails 3/3 without the fix
with the flake's exact message, passes 5/5 with it. The pair that used to flake
(`TestTmuxServerWatchIntegration|TestCreateTerminalInWorkspaceUsesItsFolder`)
is 10/10 green; the whole package 208 s ok; the shard runner 3/3 ok.
Docs: the terminal paragraph in `docs/architecture/routes.md` (born in the
workspace folder — and the creation answer names it), the `process.md` flake
bullet now carries the mechanism and the residual hazard (that watch test
mutates the process-wide `TMUX_TMPDIR`, which can still strand same-binary
tests on a server it dismantles — never observed to fail on its own).
Not verified: a Windows/macOS daemon (the race is tmux's, not the OS's, but the
measurement is Linux).
