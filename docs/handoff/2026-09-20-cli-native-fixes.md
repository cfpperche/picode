# 2026-09-20 — cli-native-fixes: adversarial review of ADR-0163, before it was deployed

Why this branch exists: the owner asked for an adversarial review of the ADR-0163 surfaces before deploying them. Three reviews ran in parallel — the config writer, the memory pane's containment and masking, and what the documentation claimed — plus direct probing of the live code. Every defect below is one the branch's own test suite and two visual-review passes had already declared clean.
The corruption class, which is the headline: the YAML locator matched a same-named block at *any* depth, so `memory.memory_enabled` was written to `foo.memory.memory_enabled` while the key the pane displayed kept its old value; the post-write parse check could not see it, because a mis-targeted write still parses. TOML was scanned with no model of multi-line strings, so a `"""` body holding `key = value` or `[table]` lines was read as configuration. JSON wrote the duplicate key every parser ignores, and appended a shadowing member under a parent that was not an object. Emptying a YAML block swallowed the comments that followed it, and emptied a whole file.
The fix shape: the locators are position-aware now — YAML anchors its first segment at the document's top level and stays inside the block its parent opened, TOML tracks string state and refuses an array of tables, and JSON refuses both ambiguities rather than guessing which copy the user meant.
Security: containment resolved the *target* file, which does not exist on a create, so a write through a symlinked subdirectory landed outside the store; listing never went through the check at all, so a symlink named `notes.md` had its first line published and a FIFO hung the pane. A relocated store is now bounded to the user's home. Masking gained the credential shapes it was missing and lost the unanchored rule that redacted the word "risk-assessment".
One schema defect worth naming on its own: Claude Code's Approvals select had no `auto`, which is what this machine is set to, so the control rendered blank beside a row saying "Set here", and any choice the owner made moved them off it. OpenCode's `autoupdate` row was withdrawn instead of fixed: it is `true | false | notify`, and a switch would destroy the third value.
Documentation: the architecture files claimed more than the code did, and those sentences were narrowed rather than the claims kept. ADR-0163 itself was left alone — an accepted ADR is immutable — so the correction rides its index row and the two architecture files.
The lesson: a green suite, a golden add-then-reset round trip over fixtures and two visual-review passes all missed a writer that puts values in the wrong place, because every fixture was a well-shaped document. Adversarial input is a different test class, not more of the same one.
State: `make close` green (fmt, vet, hooks, Go over 19 changed paths), `main` can fast-forward to `feat/cli-native-fixes`.
Durable items for these surfaces stay in `docs/handoff/open/agent-clis-native.md`, including the two the review added: the Memory pane has no toggle and the 409 no Replace control, and two of the six stores have no config key to link to at all.
