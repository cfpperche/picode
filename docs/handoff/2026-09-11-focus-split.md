# 2026-09-11 — focus-split: fullscreen mode stops taking the browser with it

Shipped: the owner's 2026-09-11 reversal of the browser half. `web/shared/domain/focusMode.js` loses the `fs` field, the `browser { active }` and `resume` rows and the whole `browserIntent` export; the decision table is now `toggle | enter | leave | unavailable | point | tick | reveal | rail | escape | seen`, ten rows, every one under test (32 pass). `web/desktop/src/lib/useFocusMode.js` loses `requestFullscreen`, `exitFullscreen`, `lockKeyboard`, `unlockKeyboard`, the `enterPending` belt-and-braces, the post-reload resume-gesture listener and the `fullscreenchange` listener; `send` is now reduce → setState → persist. Why: in real browser fullscreen the browser eats the first Escape, so the designed two-step (close the revealed strip, then leave) only survived where fullscreen was refused — the rare case was costing the everyday one; the window belongs to the reader; and `F11` composes with the mode with nothing to synchronise. The price is the keyboard lock, which the API grants only to a page that asked for fullscreen itself: the browser's reserved chords (`Ctrl+T`, `Ctrl+W`, …) now stay with the browser in every window. `browserChord.js` survives as the guard that keeps PiCode's own defaults off those chords. Docs: `docs/architecture/routes.md`, `docs-site/guide/keyboard.md` (the "gives every key to the page" section is gone, replaced by what to do instead), `docs-site/guide/getting-started.md`, `docs/changelog.d/focus-split.md`. No ADR: the mode shipped as a UI refinement under ADR-0105 and no decision record mentions the sync.
Verified: browser QA on a scratch instance (`qa-scratch.sh start focus-split`, :8472, 1440×900, terminal tab + a two-panel canvas). Context-menu entry and `Ctrl+Shift+Enter` both give `#app.focus-on` with `document.fullscreenElement === null`; the three strips reveal on dwell (left/top/right, `focus-reveal-*`, `fullscreenElement` still null at each); Escape with a strip revealed closes the strip and stays (`focus-on`), Escape with none revealed leaves (`picode-focus=0`, chrome visible); the top strip's icon-only Leave control leaves too; a reload with the mode on comes back complete — three strips, chrome hidden, nothing waiting for a gesture. The terminal fills 1424×884 of a 1440×900 window in the mode and the Canvas fills 1440×900 (876×860 outside it), so both still take the whole window with the Canvas's own floating chrome. F11: a synthesized F11 through CDP never reaches the browser UI, so the real gesture was stood in for with `requestFullscreen()` from a genuine click — with the document truly fullscreen, entering and staying in the mode changes nothing; leaving the mode restores the chrome and leaves `fullscreenElement` set (PiCode does not exit a fullscreen it did not enter); and the reader leaving fullscreen while the mode runs leaves the mode on, which is exactly what the old sync would have ended.
visual-review: PASS (6 captures read — dark and light, mode with nothing revealed, left strip revealed, canvas inside the mode; plus the top strip over the canvas and the entry context menu; `__picodeOverlayAudit()` ok for the context menu and both reveals, rows 28px aligned at 6).
Not done / debts: the reserved chords are gone for good from a browser tab — no in-app path hands `Ctrl+T` to a guest CLI any more. A revealed top strip covers the Canvas's own chrome pill (pre-existing: the reveal floats, it never pushes the layout). Real F11 was not exercised as a browser gesture, only the document-fullscreen equivalent. `CHANGELOG.md` 0.2.0 (released the same day) still advertises the browser half; the fragment corrects it in the next release, and the file is assembly-only on a branch.
Merge: fast-forward ready.
