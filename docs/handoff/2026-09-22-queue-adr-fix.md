# 2026-09-22 — queue-adr-fix: the product must not depend on our own land
The owner caught the coupling in ADR-0182's first draft: it executed the queue "through the land that already exists" and called this repository's gate receipts the queue's evidence — but `land.mjs`, `ci.sh` and `delivery-receipts.mjs` are **our** development flow, not a product capability. That is D2's failure one layer down: a product surface only PiCode's own project could use. The direction, in the owner's words: our workflow uses PiCode's delivery tooling; PiCode does not depend on our land.
Corrected in the ADR (still `proposed`, so this is an edit and not a supersession): the queue executes the integration **a project declares** — target branch, merge policy, the command(s) that must pass — through PiCode's own runner; this repository's `make land` is one such declaration and may become a *client* of the queue, never its engine. Receipts stay the product's format (ADR-0170's bounded producer receipts) and any producer may write them: this repository's gates do, so its entries arrive with evidence, while a project that writes none is observed as unknown, never as a fabricated pass. The rejected alternative is recorded with that reason, the index row and the earlier session note were corrected in place, and the "how integration runs" declaration is now itself a named blocker when a project has not made one.
