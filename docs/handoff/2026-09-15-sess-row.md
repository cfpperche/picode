# 2026-09-15 — sess-row: clamp both lines of a session row

Owner-reported from two screenshots: the Sessions tab rows break — a long preview (a Muse Code prompt, a Grok prompt history entry, a quoted Windows path) runs past the card and pushes 'Open in terminal' and the row menu outside it; in another row the model name paints over the 'age · size · msgs' facts.
Cause, measured in the browser: the preview lives inside `.mcp-row-actions`, which is `flex-shrink: 0` (right for a package row's buttons) plus `flex-wrap: wrap` on `.sess-row`, so a long preview sized the cluster to its whole text (emulating the old rule on the quoted-path row put the cluster 351 px past the card); and `.sess-meta` (the model, a nowrap secondary attribute) could not shrink below its min-content, squeezing the name to 0 width and painting over `.sess-facts`.
Fix, both sheets (`web/browser/src/styles/app.css` and `web/mobile/src/styles/mobile-sessions.css`): `.sess-row .mcp-row-actions { flex: 1 0 100% }` (the row is now two deterministic lines: identity + facts, then preview + buttons), `.sess-row .sess-meta { flex: 0 1 auto; min-width: 0; overflow: hidden; text-overflow: ellipsis }` and buttons stay `flex: none`; the existing `.sess-preview` clamp then does its job.
Verified on a scratch with real data copied in: the owner's Muse index (2 sessions, one with the long '[Image #1] quero que pesquise na web referencias de layouts...' prompt) and a Grok `prompt_history.jsonl` (28 sessions, including the quoted 'C:\Users\cfpp\Pictures\Screenshots\...' previews): every one of the 30 rows reports 0 overflow, the actions cluster inside the card, both lines deterministic, previews clamped with an ellipsis, pageScrollX 0; mobile 390 px sheet rows stack with the buttons inside; the empty state reads 'No Antigravity sessions yet' + New terminal.
The fix is class-scoped to `.sess-row`, so every CLI's Sessions tab (including Pi's own pane, which uses the same CliRow markup) gets it.
