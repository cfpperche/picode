# 2026-09-21 — picode-env-audit: every PICODE_* the runtime exports, audited

Shipped: `scripts/go-test.sh` unsets the **whole ambient `PICODE_*` family**
for every test invocation (dynamic `-u` list from the environment; was only
`PICODE_TERM_ID` + `PICODE_DATA`). Tests that need a value keep using
`t.Setenv`, which overrides regardless.

Method: every `PICODE_[A-Z_]+` referenced under `internal/` and `cmd/`
(45 distinct names) was classified by reader and by whether its test files
pin it — generated by script, not by hand. The full matrix is one command
away (the generator in this branch's history); the verdicts:

- **State/identity resolution, process-wide** — the leak class that bit twice
  (`PICODE_DATA` wrote fixtures into the live vault; `PICODE_TERM_ID` split
  the test cache): `PICODE_DATA`, `PICODE_HOST`, `PICODE_PORT`,
  `PICODE_INSECURE`, `PICODE_PUBLIC_URL`, `PICODE_TERM_ID`, `PICODE_TERM_URL`,
  `PICODE_AGENT_ID`, `PICODE_INSTANCE`, `PICODE_TOKEN`, `PICODE_URL`. All
  pinned in their packages' tests except `PICODE_TOKEN`/`PICODE_URL`
  (`mcptool` client — its tests construct clients explicitly; no known
  failure), and now all stripped at the gate layer regardless.
- **Terminal-scoped hook/intercept vars** (`PICODE_HOOK_*`,
  `PICODE_OPENCODE_*`, `PICODE_TUI_*`, `PICODE_NATIVE_*`, `PICODE_CHECKLIST`,
  `PICODE_INTERCEPT_BIN`, `PICODE_MESSAGES_*`): consumed by hook scripts and
  the terminal wiring; harmless in tests unless read, and the tests that read
  them pin them.
- **QA-tooling vars** (`PICODE_QA_*`, `PICODE_PLAYWRIGHT_MODULE`,
  `PICODE_DEMO_APP`): QA scripts only.
- **Flag worth knowing**: `PICODE_DEPLOY_FORCE` set in a shell makes
  `picode deploy` skip the mid-turn refusal from that shell. Nothing in the
  repo sets it; it only travels if a person exports it.

Verified: family-wide unset proven under `bash` (ambient `PICODE_DATA` and
`PICODE_TERM_ID` arrive unset inside the stripped environment); script syntax
checked; affected suites green.

Not done: `internal/config` is the only boot-time reader left unpinned at
the TestMain layer — its own tests pin every variable, and no other test
calls `config.Load` without pinning, so no change was needed.
