# 2026-09-24 — feat/go-test-portable: the split worked, and my own path was GNU-only

The first run of `go-heavy` measured the promise: the main Go job fell from **41 minutes to 7** on ubuntu (it no longer waits behind the pair), the heavy job took 35, and the wall went from 41.5 to 35 — the two halves stop competing for two cores.
It also went red on `Go (macos-latest)`, and the cause was mine: `scripts/go-test.sh` built its heavy-package pattern with `paste -sd'|'`, BSD `paste` answers that with its usage line, so the pattern was empty and every downstream match became a silent no-op. On macOS `internal/server` therefore ran inside the job that had just excluded it, with that job's ceiling, and died at `panic: test timed out after 25m0s` — a red that said nothing about the package.
The defect predates the split (the same empty pattern made sharding a no-op on macOS); the split only made it load-bearing. Both `paste` calls are gone for POSIX `tr`, the pattern cannot be empty without failing loudly, and the main job's ceiling is 35m — sized for the macOS half, whose real time the red run never measured.
Verified: pattern construction `[a/b|b/c]`; `GO_TEST_EXCLUDE_HEAVY=1 ./scripts/go-test.sh ./internal/llama ./internal/store` runs 1 package and leaves `store` out; the shard path still works (`GO_TEST_HEAVY=…/internal/llama GO_TEST_SHARDS=2` → 2 shards); `bash -n`; the workflow guard 29/29.
