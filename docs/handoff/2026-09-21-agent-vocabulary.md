# 2026-09-21 — agent-vocabulary: the delivery docs called agents "guest CLIs"
Found: today's delivery work (`feat/delivery-tool`, `0456e595`) described a "guest CLI" beside a "Pi agent". That split is the pre-ADR-0160 frame. A workspace instance of any launchable CLI **is an agent** (`agents.cli`, ADR-0160), the principal is the agent id, `launchIdentityEnv` writes `PICODE_AGENT_ID` into its terminal and `grant.FromIDs` resolves agent-wins; `managed_clis` migrated onto `agents` and the table is gone (`docs/architecture.md`). Only unbound `#/clis/new` terminals and project shells stay terminals. "Guest" survives on the packages side alone (ADR-0167: the eight non-Pi CLIs' own plugin scopes, never an agent scope).
Origin of the wording: ADR-0154's Context ("guest CLIs", written 2026-09-18, a day before ADR-0160) plus the runtime phrasing in `internal/server/cli_tools.go` and `CliLaunchSettings.jsx`; I did not read ADR-0160 or `docs/architecture.md` before writing the docs.
Fixed, same session: `docs/architecture/delivery.md`, `docs-site/guide/delivery.md`, `docs-site/guide/packages.md`, `packages/pi-delivery/README.md`, `packages/pi-delivery/src/logic.ts`, `internal/mcptool/delivery_test.go`, `docs/handoff/open/delivery-flow.md`, the `2026-09-21-delivery-tool` note and the changelog fragment — each now names the agent and how the tool arrives for its CLI (MCP at launch, the CLI's Connectors scope, or the Pi package).
Not wrong, checked: the implementation. `managedCLILaunchOverrides(agent.CLI)` runs at agent creation (`internal/server/agents.go`) and `fillManagedCLITools` fills every family when the settings were never touched, while the picker's saved config is what a launch reads (`internal/server/cli_launch.go`). The narrower truth stands: what the form could not do was switch delivery on for an agent whose launch settings had been customized.
