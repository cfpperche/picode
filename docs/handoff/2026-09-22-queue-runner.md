# 2026-09-22 — queue-runner: the operation runs, once per repository
Slice 3 of D3. Authorization is now execution authority: authorizing an entry drains that repository — the entry just authorized, then whatever else is authorized behind it, in the order the owner set — and one repository runs **one** operation at a time. That is enforced twice on purpose: the store refuses `start` while another entry of the repository is running, and the daemon holds a live lock per repository, so neither a forgotten check in a route nor two racing triggers can run two integrations into one branch.
**The runner** (`internal/delivery.RunEntry`) re-reads what the entry was authorized against and names every way it went stale: no declaration, a declaration that is not fast-forward-only, the branch off the reviewed revision, the target gone or moved past a fast-forward, or recorded evidence of failed checks — each recorded as `failed` with `not run: <reason>`, never as a silent move. Then it runs the declared commands through `/bin/sh` (30 minutes each; the declaration is the owner's text, so an agent cannot put a command there) and moves the target fast-forward only: a branch a worktree holds is merged there — Git refuses a dirty tree and anything not a fast-forward — and a branch no worktree holds moves by compare-and-swap, so a target that changed under the run is a refusal instead of a lost commit.
**Recovery**: an entry left running when the daemon stopped is marked with the outcome unknown — no retry, no inferred success — and the owner's withdraw (now allowed on a running entry) is the way out of a wedged repository. Startup also drains whatever is authorized, which is how the queue survives a restart.
Found while testing, two corrections in the store: the one-run-per-repository guard queried the database *outside* the transaction that held the write lock, which deadlocked the first test run (it now queries through the transaction); and `fail` was refused from `authorized`, though a blocker is exactly "an authorization that no longer holds" and never passed through `running` — the decision table now allows it, and `finish` stays `running`-only. `Observe` was also not injectable, so the evidence blocker could only have been tested by hand-writing receipt files; it is now a package variable like `git` already was, and the blocker is covered. Tests: the runner against a real repository (integration with two declared commands, the compare-and-swap path leaving the checkout untouched, five blockers with the target pinned, a failing command naming itself, and a second entry refusing to start), the store's serialization and unknown-outcome/idempotence tests, and two end-to-end tests through the doors (authorize → done with `main` moved; a failing declared check → failed, `main` untouched).
Not in this slice: the runner records the operation on the entry, not yet in the product's receipt format, and `/bin/sh` means Windows is untested. Both are in the topic's Next/Debts.
