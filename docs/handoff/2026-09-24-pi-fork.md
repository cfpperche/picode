# 2026-09-24 — pi-fork: Fork agent… for Pi agents

Paid the agent-fork debt "Pi agents are not offered Fork". A third fork shape,
`clisession.AgentForker` (`pi_fork.go`): pi's own `--fork <file> --session-id <id>
--session-dir <new agent's folder>` runs once, headless (extensions/skills/templates/
themes off, stdin closed; 0.31 s measured on pi 0.87.1), after `createCLIAgent`
creates the agent and before its first start (`cliTerminalRequest.session` hook), and
the file becomes the new agent's `SessionPath`. Measured: pi writes the copy at once,
entries byte-identical, `parentSession` set, header cwd = the folder it ran in.
`agent_fork_pi.go` resolves the source (SessionPath → pending id → newest file), keeps
the source's launch overrides, and sends the task through `deliverForkTask`. Pi's
capabilities now claim fork; the Pi agent menu offers Fork agent… once the agent has a
session or has run. Failure removes the new agent (502 with pi's message).
Built on `feat/muse-fork` (reuses `deliverForkTask`); land after or with it.
Verified: fake-pi unit and server tests (a mutation dropping the pin fails them);
live on a scratch instance with the real pi: copy in the new agent's folder, source
untouched, history shown, a two-line task delivered and answered, Restart relaunches
with `--session <copy>`. visual-review PASS (menu + dialog). Scratch Pi first asked to
trust the folder (untrusted scratch HOME); the task waited and landed after it.
