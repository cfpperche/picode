# 2026-09-23 — queue-mode: the declaration names its engine
First slice after ADR-0186. `IntegrationSettings` gains `mode` (`local`, `provider`, or absent), validated and persisted per scope with the same workspace → machine fallback; the runner refuses `provider` with `not run: this project integrates through its own provider…`, refuses an undeclared mode with `not run: the project declares no integration mode…`, and the owner's `order` is refused under `provider` because the provider owns the order. Provider mode carries no commands (its provider runs those checks) and the declaration refuses the combination.
The surface follows: Preferences → Landing work and a workspace's own rules gain a **Who integrates** select, hide the checks under provider with the reason in one line, and the sentence above the editor follows the draft — found by looking at the rendered page, where the old copy still promised that PiCode runs the checks and merges, which is false under provider. Domain helpers (`rulesSummary`, `blocksLanding`, `integrationIntro`, `integrationSave`, `draftFrom`) and their tests carry the modes; the browser and mobile surfaces are kept in step.
Behavior change worth naming: a declaration that names no mode no longer executes — an authorized entry is ejected with the mode reason, and both the settings surface and the read say so. That is ADR-0186's rule (absent is a blocker, never a guess) applied to declarations written before it existed.
Not in this slice: the provider path itself (enqueueing through the project's queue, reading position and ejection) — that needs a vendor fixture and is the topic's next item.
