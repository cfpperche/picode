# 2026-09-14 — cli-face: CLI terminals show their mark, name, and Open

Shipped: owner-reported from two screenshots — Muse Code and Antigravity terminals in the sidebar used the default terminal icon, subtitle "Shell session" and status "Terminal open", while other Agent CLIs showed their mark, name and Ready/Working.
Cause: every identity surface resolved the CLI with `terminalCli(term)` (`tui.cli` else `cli`); a CLI without an adapter never reports a runtime, and only `launchCli` names it. Fix: `terminalDisplayCli` (runtime CLI, else `cli`, else `launchCli`) used by TerminalCliBadge, WorkspaceRows TermRow, AgentTabs titles, ProviderFaces TermFace, canvas hints, mobile TermRow, and the dashboard fleet bucket. `terminalCli` keeps the activity/handoff/not-reported semantics. `terminalStatusLabel` reads "Open" for a CLI terminal with nothing to report and "Terminal open" for a plain shell.
Second defect while verifying: a terminal created while the page was open stayed a shell until reload — the store's `terminal.created` carries the bare row (no `launchCli`/runtime) and creation published nothing else. `createCLITerminal` now calls `publishTerminalState`; `applyFleet` lets a complete `terminal.changed` view seed an unknown row (the two frames race). Tests: `TestCLITerminalCreationAnnouncesItsIdentityOnTheFeed`, `TestCLITerminalRefusedLaunchCreatesNoRow` (a refused launch creates no row), `terminalDisplayCli` + status-label cases, and the fleet reducer race case.
Verified: isolated scratch (`TMUX_TMPDIR`); a terminal created live shows the Antigravity/Meta mark with "Open" in the sidebar and the tab, mobile row included.
INCIDENT: the QA session ran `tmux kill-server` with `TMUX_TMPDIR` set and took the production tmux down; the owner restored 6 of 10 sessions (Antigravity, canvas, canvas2, codex stayed stopped). AGENTS.md gained a "Never tmux kill-server" rule.
