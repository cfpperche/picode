# 2026-09-19 — the mode now survives a page load (feat/annot-nav)

Paying the debt the channel fix named: `REINJECT_SCRIPT` was defined and
never called, so a full navigation (a link, a reload) threw the script away
while the strip kept claiming the mode was on.

## What landed
- `NavigationCompleted` per armed tab re-executes REINJECT_SCRIPT; the set
  of armed tabs it reads is written on arm/disarm and pruned on close
  (the old `annotate_tabs` was written, never read, never pruned).
- The hook is (re)subscribed per arm with its token, like the message
  receiver, so re-arming never double-fires and a recreated webview gets a
  live hook.
- Evidence: `make desktop-shell` cross-build green, and the constant's
  "never used" warning is gone (warnings 7 → 5; the two `unused Result`s on
  `with_webview` cleaned too). Rust 13/13, incl. a static guard
  (`the_shell_reinjects_on_a_completed_navigation`) — falsified by renaming
  the call, which makes it fail.
- Page-side half proven in the committed harness with a REAL navigation:
  script gone after `?page=2`, then one injection arms it again and posts
  `enter` + `state`. That is exactly what the hook does.
