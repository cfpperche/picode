## Slice 2 — the CDP bridge (next session, fresh context)

Goal: agents read/act on the SAME pages the human sees, over the
authenticated shell-daemon channel — no open port (ADR-0128).

Increments, each shippable on its own branch:

1. **Screenshot button** (read tier seed): `btab_screenshot` command in
   `btab.rs` using `ICoreWebView2::CapturePreview` (webview2-com crate —
   NOT CDP; async with a handler, needs `windows`/`webview2-com` deps in
   desktop-shell/Cargo.toml). Toolbar button "Take a screenshot" saves to
   the workspace; PNG shown as a toast/preview. Pure COM callback work —
   budget a session for it alone.
2. **CDP call bridge**: `btab_cdp_call(id, method, params_json) ->
   result_json` via `ICoreWebView2_4::CallDevToolsProtocolMethod` +
   `ICoreWebView2_4::add_WebResourceRequested`-style event receiver for
   CDP events; per-tab event ring buffer polled by `btab_cdp_events`.
3. **Tier gate (host-side, deny-by-default)**: method allowlists from
   ADR-0128 — read: Page/DOM/CSS/Network/*, Emulation.*; act: read +
   Runtime.evaluate + Input.*; full: act + downloads/clipboard/PDF.
   Enforced inside the command before the COM call (policy unbypassable:
   the webview never sees a raw port).
4. **Agent exposure**: daemon endpoint proxies to the shell over the
   existing authenticated channel; Pi tool `browser` (read first, act
   behind per-agent permission, slice 4 builds the policy UI).

Read before starting: docs/plans/desktop-v2.md (browser section, slices
mapping at its end), docs/decisions/0128*.md, desktop-shell/src/btab.rs
(async commands, BtabState holds Webview by label).
