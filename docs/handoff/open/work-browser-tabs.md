## Overlay over the page — the settled mechanism

HTML popovers can never paint over a WebView2 sibling. Attempts tried:
z-order flip via SetWindowPos (btab_layer) FAILED — the UI webview is an
opaque full-window surface; raising it paints gray over the page.
REMOVED. Settled: while the menu is open, the page webview slides down
by MENU_H (96px) via the regular bounds push (menuOpenRef offset in
push()); page stays visible the whole time. Closing restores.

## Traps (all paid for, more than once)

- EDIT IN THE WORKTREE. Three times UI edits landed in the root checkout
  and scratch/deploy silently tested stale bundles. Pattern that works:
  edit root by accident → git diff > patch → apply in worktree → build
  there. Better: open files under .worktrees/browser-lab directly.
- toast(msg) defaults to kind "err" (red icon) — success needs toast.ok.
- `.web-tab-toolbar button` beats bare class selectors — prefix toolbar
  button overrides with `.web-tab-toolbar`.
- um-popover is styled for the user menu context; don't reuse elsewhere.
- data-URL downloads are blocked inside WebView2 — never ship downloads
  from the shell UI; write files from Rust and toast the path.
- Async tauri commands for anything creating/manipulating webviews
  (sync commands run on the main thread → lab v1.0 freeze class).
- webview2-com-sys 0.38 pins windows/windows-core 0.61 — keep them
  aligned; COM handlers come ready-made (CapturePreviewCompletedHandler,
  CallDevToolsProtocolMethodCompletedHandler — see webview2-com callback.rs).
