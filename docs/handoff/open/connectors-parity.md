# Connectors parity (ADR-0150) — durable debts

## Debts

- [x] Guest codecs are strict: OpenCode itself writes trailing commas (JSONC-ish) into opencode.json and our parse error blanks the whole pane. Fix: tolerate/normalize trailing commas where the vendor does, and degrade malformed user files to a blocked state naming the file (one line + action) instead of a pane-wide error. Repro 2026-09-18: owner real file had `,}` after schema-only config.
  Paid 2026-09-18 (feat/connectors-codec-robustness): lenient JSONC reads (strict writes), per-layer `error` degradation on GET /api/mcp for every CLI codec (JSON, TOML, YAML), pane blocked line + Open/Retry, `/api/mcp/reveal`.
- [x] Phase 2–4 driver formats were written from vendor docs unverified against real binaries (omp/agy shapes, opencode/grok blocks, muse/hermes files).
  Paid 2026-09-18 (feat/connectors-parity-live): every driver exercised against the real binaries via `internal/connectors/live_test.go` (sandbox HOME, vendor CLI as oracle). Five divergences found and fixed with tests — Claude add argv + list-line health tails, Codex and AGY workspace layers never loaded by the vendors (removed, project scope refuses), Grok does have a toggle (`enabled` + `disabled_mcp_servers`, implemented), OpenCode's own store is `opencode.jsonc` (jsonc wins conflicts; layers + target resolution), Muse requires `schema_version` (kept present on every write). Omp proven to load both driver files and honor `enabled` via spawned-server marker.
- [ ] OAuth sign-in cannot complete headlessly for any vendor. Command shapes verified live (`claude mcp login <name>` refuses honestly without a TTY; `codex mcp login`, `opencode mcp auth`, `muse mcp login --headless`, `hermes mcp login` all exist and parse), but the browser round trip needs a human. Owner check: run the pane's copyable sign-in command for one OAuth server per CLI (claude-code, codex, opencode, muse, hermes) in a real terminal.
- [ ] AGY inside a real session: whether a session loads a workspace `.agents/mcp_config.json` is untestable headless (Google auth blocks before MCP init). `agy mcp list` resolves only the user file, which is why PiCode manages only it. Re-verify with an authenticated session before ever restoring a project layer.
- [ ] Muse load-time behavior beyond entry recognition: `enabled: false` at spawn time and `headers` on streamable_http entries were not observable through `mcp login` alone (it only proves the entry was found and its transport read). Verify with a live muse session against a reachable HTTP MCP server.

  Paid 2026-09-19 (feat/connectors-status-parity): claude reuses its list health tails (✓/✘), opencode parses `mcp list` state glyphs, hermes its status column; probes run per pane load (15s budget, 60s cache, skip on hung/missing CLI).
