# 2026-09-22 — queue-agent-door: the agent can ask for a place, and see what it asked for
Slice 2b of D3, on top of the accepted ADR-0182 and the owner's doors. The agent's half of the queue now exists on all three faces of the `delivery` tool — the `picode delivery` command, the MCP family, and the pi package — through one contract, so no face offers an action another refuses (the package's `ACTIONS` and the MCP enum are compared by a test).
**`request-integration`** asks for a place for the launch's *own* delivery, naming the revision and target that delivery declares; another launch's delivery is a 403, not a silent write. **`withdraw-integration`** steps out of the queue by the entry's own id and version, which `show` now prints (the tool's `show` payload gained `queue`). `capabilities` advertises the queue, the agent actions and the owner actions separately — the agent may not order or authorize anything, and the store is where that is enforced.
Found while wiring it: the store accepted whatever revision the caller named, so an agent could have queued a revision nobody reviewed. The enqueue now **checks** the revision and target against the delivery's declaration and refuses a mismatch — a check, not an override, so a stale request is named instead of absorbed. Deployment stays refused with its own message.
Tests: the agent's walk end to end (drifted revision refused, request → waiting with the right principal, exact retry replays the same entry, a second request refused, `show` carries the entry, a foreign launch gets 403 on both actions, a stale version is 409, the owner authorizes, the agent withdraws from `authorized`, and the withdrawn slot frees a fresh request), the new refusal rows in the table test, the store's mismatch test with the per-delivery read, and the package's own shape test.
