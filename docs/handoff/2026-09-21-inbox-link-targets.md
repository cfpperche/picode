# 2026-09-21 — inbox-link-targets: app-feed links open as work tabs, never over the shell

Incident: on 2026-09-20/21 the owner clicked a github.com URL inside an Inbox feed item (an app surface, ADR-0036) and it navigated the desktop shell's whole document — the shell UI was lost, recovered by history back / relaunch. Markdown detail blocks mint plain anchors, and a plain anchor's default is hosting-document navigation.
Implemented (2bc7bd61): one delegated guard, `surfaceLinkClick` from `web/shared/client/surfaceLinks.js`, hung capture-phase on each AppSurface root — browser and mobile, both render modes — so every block renderer is covered, present and future. The pure decision (`surfaceLinkPlan`) reuses the externalLinks.js table with a different destination: an absolute http(s) URL off-origin opens as a work-browser tab in the shell (`onOpenUrl` → `openWebTab`, the address-bar flow: new `w:` tab, workspace pane focused, `btab_navigate`); outside the shell the anchor gets `target="_blank" rel="noopener noreferrer"` and the native default runs. Same-origin, relative, hash routes, and mailto:/javascript: keep native behavior; clicks another door already took (defaultPrevented — the system-browser bridge answers explicit `target=_blank` at document capture, ahead of any surface) are left alone.
Verified: `web/shared/client/surfaceLinks.test.js` walks the decision table (incident row, in-app rows, guard behavior in both hosts); `make ci-scoped` and `make close` green on this branch.
Limits: an explicit `target=_blank` anchor inside app markdown keeps the existing system-browser door (document capture outranks the surface) — feeds mint plain anchors, so the Inbox case is covered. No changelog fragment: the fix is the intercept itself; no data or renderer change.
Deployment: the built UI on disk was refreshed at land; the owner reopened the shell and **accepted live (2026-09-21)**: the feed's GitHub link now opens as a work-browser tab and the shell stays put.
Integration: landed on main (59a6b53d).
