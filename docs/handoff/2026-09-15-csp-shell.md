# 2026-09-15 — feat/csp-shell: the policy finally reaches the app's own URLs

Owner-approved follow-up to the dev-server preview: the gap I reported (the
shells' directory URLs carried no CSP) was worse than "one line", and the two
halves had to travel together.

Coverage: `securityHeaders` matched only `/`, `/index.html` and `*.html`, but
the launcher sends a browser to `/browser/`, a phone to `/mobile/`, and the
Windows shell loads `/desktop/` — so in practice every shell ran with **no
policy**, and the `/pair` exception aside, ADR-0052's amendment was enforced
only on the launcher page.

Hash: the launcher's `index.html` has no inline script; each shell's has the
theme bootstrap (623 B browser/desktop, 1631 B mobile). `inlineScriptHashes`
read the launcher's file for every path, so adding coverage alone would have
**blocked** that bootstrap — the test's second failure mode. It now maps the
path to its file (`htmlFileFor`) and memoizes per file for an embedded build.

Tests: `TestEveryServedShellCarriesItsOwnHash` (one row per shell: policy
present, one `'sha256-'` per inline script, hash matching) and the shape test,
which used to skip on every run (its skip keyed on the launcher having a
`<script>`, and its `unsafe-eval` assertion contradicted `'wasm-unsafe-eval'`).
Both run against a written UI fixture. Reverting each half in place makes them
fail ("served without a CSP"; "1 inline script(s) in the page, 0 hash(es)").
QA on a scratch (:8474): policy on all four paths, none on `/assets/*`; zero
`securitypolicyviolation` in the browser shell (terminal WebSocket live) and in
the mobile shell; theme bootstrap ran in both; the dev-server frame renders
(screenshot `var/screenshots/csp-frame-ok.png`).
Docs: amendment in `docs/decisions/0052-public-access.md` (the decision this
completes, including the `frame-src` widening that shipped with the preview),
`docs/architecture/devservers.md` corrected, changelog fragment.
Not verified: the Windows shell itself (no Tauri host here) — it loads the same
`/desktop/` bundle and the same inline script as `/browser/`, which is covered.
visual-review: PASS (5/5)
